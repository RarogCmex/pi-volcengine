# Research: изменения доков Volcengine Ark / API Gateway (2026-09-22)

Статус: **не верифицировано живыми пробами** — на момент исследования доступного
ключа не было. По правилам [`AGENTS.md`](../AGENTS.md) ничего из этого не вносится
в каталог `index.ts` и README, пока не подтверждено E2E; файл публикуется как
дорожная карта повторной проверки, а не как факты о шлюзе.

Источники — официальные доки Ark (docs.volcengine.com, обновления 2026.09.08–09.17)
и чейнджлог продукта API Gateway, на котором работает шлюз volceapi.com. Сам
volceapi.com на момент исследования не отвечал, поэтому всё ниже — по докам, а не
по ответам шлюза. Каталог расширения верифицирован живьём 2026-09-15.

## Vision / мультимодальность (Responses API)

- Модели версий **250615+ по умолчанию принимают мультимодальный вход** через
  Responses API (image / video / document / audio).
- `input_image.detail`: значения **low / high / auto / xhigh** (xhigh —
  максимум деталей, медленнее). Дефолт для doubao-seed-1.8+ — `high`.
- Новый параметр **`image_pixel_limit: {max_pixels, min_pixels}`** —
  приоритет выше `detail`.
- **`file_id`** через Files API (хранение 7 дней) и **TOS URL**
  (`tos://bucket/...`, авто-пресайн; видео до 2 ГБ) — работают и в Responses,
  и в Chat API.
- Лимиты изображений: 50 МБ/файл, 64 МБ тело запроса, до 3600 изображений на
  запрос, URL-суммарно 200 МБ; HEIC/HEIF только doubao-1.5-vision-pro+.
- **DeepSeek-V4.1-Flash** (`deepseek-v4-1-flash-260910`) — новая модель,
  заявлена поддержка понимания изображений; **DeepSeek-V4-Pro** — «нативная
  визуальная поддержка». В нашем каталоге `deepseek-v4-flash`/`deepseek-v4-pro`
  помечены `input: ["text"]` по живой пробе от 2026-09-15 — кандидат на
  перепроверку (шлюз может отличаться от прямого Ark).
- Свежий флагман Ark — **Seed-Evolving** (`doubao-seed-evolving`). В статике
  его нет; динамический оверлей `fetchModels` подхватит автоматически
  (консервативно: chat-completions, text-only, без thinking).

## API Gateway (продукт под volceapi.com)

- **2026-08**: многооконный Token rate-limit на потребителя (5 ч / неделя /
  месяц) — вероятный источник новых текстов 429-ошибок; хук нормализации
  переполнения их уже игнорирует (RATE_LIMIT_RE).
- **2026-09-10**: **AI Model Fallback** — автопереключение на запасную модель
  при ошибке основной. Следствия для нас: `model` в ответе может не совпасть
  с запрошенным (pi-ai фиксирует как `responseModel`), а списанный кредит —
  отличаться от множителя выбранной модели.
- **2026-09-10**: заявлена поддержка Anthropic-моделей в AI-шлюзе.
- Единственное место, где источник ненадёжен: в чейнджлоге заявлено, что «Responses API теперь по умолчанию
  возвращает `reasoning.encrypted_content`», но независимым поиском это не
  подтверждено (страница SPA, первоисточник не читается). Для расширения безвредно: pi-ai всегда шлёт
  `include: ["reasoning.encrypted_content"]`, шлюз его принимает и (проба
  2026-09-15) ничего не возвращает.

## Чек-лист живых проб для повторной проверки

1. `deepseek-v4-pro` / `deepseek-v4-flash`: отправить `input_image` — если
   vision работает, расширить `input` и обновить шапку/README (дата!).
2. Проверить принятие `detail: "xhigh"` и `image_pixel_limit` на
   vision-маршрутах (doubao-seed-2.1-pro, glm-5.3-flash, qwen3.8-*).
3. `/volcengine models refresh` — появились ли в листинге шлюза
   seed-evolving / deepseek-v4.1-flash / anthropic-модели; если да — снять
   капы, effort-карты и retention живыми пробами и добавить в статику.
4. Fallback: сравнить `model` в ответе при форсированной ошибке основной
   модели — убедиться, что подмена не ломает тарификацию/хуки (модель в
   payload vs. модель в ответе).
5. Заодно перевалидировать retention-матрицу (`prompt_cache_retention`) —
   апгрейд совместимости Ark от 2026-09-09 мог снять «json: unknown field»
   с deepseek-v4-flash / doubao-seed-2.1-pro / glm-5.2.
